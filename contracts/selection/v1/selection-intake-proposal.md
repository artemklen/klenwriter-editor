Text points are UTF-16 at SDK boundary, structural points remain structural; Rust checks scalar boundaries and owns semantic edits. Visual bidi remains browser layout/navigation. `docs/m0/architecture.md:122`, `:139`, `:149`, `:165`; master plan v3 `docs/m0/master-plan.md:11`, `:19`, `:25`.
- ADR-003 distinguishes scalar-readable points from EGC-editable ranges, includes clusters across differently marked adjacent text leaves, preserves literal Unicode, orders normalization maps, distinguishes mapped/deleted/stale/invalid and forbids nearest-DOM fallback. Undo restores historical identity while revision remains monotonic. `docs/m0/unicode-positions.md:20`, `:22`, `:26`, `:30`, `:45`, `:51`, `:57`, `:61`. Its illustrative `leaf/utf16` property names are not the actual wire spellings.

Context is build/profile tuple + registry/capability digests (`packages/wasm/src/sdk-types-v2.ts:10`). No flattened document offset, character unit for an atom, or persisted DOM path is needed.
- Current mounted facade already has guarded `capture/context/read/query/submit/subscribe`, modes, explicit replace/destroy and resources (`packages/dom/src/types.ts:48`). - Current internal view has owned-object mapping and scalar checks (`packages/dom/src/view.ts:168`, `:196`), anchor/focus restoration without focus stealing (`:213`) and affinity retention when the same actual DOM endpoints survive (`:239`). Cloned attributes/IDs confer no authority. Current input only has a narrow outside-control keyboard-Tab return guard, restoring the **current** native selection (`packages/dom/src/input.ts:219`); pointer entry keeps its own intent. ## Proposed requirements and smallest API boundary

Keep generated wire types, the mounted SDK2 ownership domain, Rust command/profile authority and the SDK event pump. The first implementation can be an internal, bounded per-mount selection controller; no second document model, layout engine, new native arbitrary setter, or public map journal is required. Existing `read(state/node/map_position)` and one `submit(set_selection)` suffice for checked publication. If host UI needs an exported bookmark in this task, freeze a thin opaque per-mounted capability before coding; possible spelling is `captureSelectionBookmark()` / `restoreSelectionBookmark(bookmark, {policy:'exact'|'mapped'})`. These names and any new DOM diagnostic code remain **proposals**, not additions to the accepted 39 API.

Bookmark contract regardless of spelling:

1. Capture owned model anchor/focus with affinity, full stamp/context and per-mount identity. Do not store a live Range or DOM objects as durable identity. Bound retained bookmarks and release on replacement/destroy; external objects cannot forge ownership.
2. Exact restoration requires the same mount/session/generation/context and applicable stamp, especially selection_epoch. Outside focus alone does not change the target or publish an incidental browser-reset range. Restore current valid selection for both Tab/Shift-Tab re-entry and an explicit focus-out/back path; intentional pointer placement/new user selection wins.
3. Never restore over a newer user selection, another mounted host/control's range, provisional input/composition, unresolved queue or recovery state. Do not focus the editor merely because a read/map completes. Pending request invalidation and selection provenance must distinguish an incidental focus reset from a real user selection; map success alone cannot establish user intent.
4. Default stale behavior is refusal. Explicit mapped restoration checks both endpoints through every retained native map, same context/generation and final current stamp before one selection submit. `deleted`, `stale`, `invalid`, missing maps or ambiguous target refuses by default; no nearest text/gap guess. A documented non-destructive policy may accept deleted provenance only if independently specified. Selection_epoch changes from document mapping versus intervening user selection need an explicit controller policy; do not equate revision maps with permission to overwrite the latter.
5. Preserve original native Response/Submission/queue outcomes and native diagnostics. DOM ownership/representation failure is a separate DomRefusal, never fabricated native atomic refusal. A selection-only publication changes the epoch/event only as native specifies: no document revision, history unit, dirty/content/ID mutation. Read/query and failed restoration are facet-pure.

### Explicit UTF-16 units ↔ scalar-boundary validation

**Native `PositionDto.text.offset` remains a UTF-16 code-unit count, not a Unicode scalar index.** The bridge validates scalar boundaries without changing coordinate units. A DOM Text offset must be a finite in-range integer and not bisect a surrogate pair. Reject such a point unchanged; never clamp/round, replace a surrogate with U+FFFD or search a nearby EGC. Element offsets map only through the actual owned text wrappers/child objects/placeholder or structural edge. Foreign nodes, stale objects, cloned IDs and unsupported topology refuse without publishing another range. Empty placeholder BR maps to Child(parent,0), not a hard-break model node.

Scalar-valid `e\u0301` offset1 may be represented/read as a selection. It does **not** authorize delete/replace/format through the cluster; Rust's pinned segmentation and profile command decide. `Intl.Segmenter` may be a labelled comparison observation, never production authority or expected-output generator. Same-cluster text across mark boundaries remains one EGC; hard_break/inline atom forms a barrier. Preserve anchor/focus order and affinity independently of a normalized DOM Range; affinity is insertion attachment, not left/right visual direction.

## Copy/cut boundary belongs to 40; full clipboard pipeline remains 47

40 must prove that an owned native selection identifies the exact intended content for copy and that cut deletes exactly that scope after a successful clipboard write, with original outside metadata intact. Include forward/reverse and structural selections, read-only copy permitted/cut refused, external-control range untouched, stale/composing/unsupported ranges safely refused, and clipboard write failure causing **no deletion**. Capture synchronous actual ClipboardEvent payloads and native before/after state, separately from a controlled DataTransfer unit lane. Installed system clipboard round-trip is a separate provenance lane, never inferred from an overlay or selection screenshot.

Before fixtures freeze, specify exact plain-text projection for authored hard_break, paragraph/list boundary and selected atom (separator/label/omission or explicit unsupported representation). Do not invent U+FFFC or turn an atom into one native character to ease offsets; do not silently normalize decomposed text. Preserve an explicit structural-membership oracle even when plain text omits an atom. This scope does not claim external HTML decode, sanitization, arbitrary paste/import, media loading or the complete multi-format clipboard contract of OSR-47. A missing public native range-cut gesture, if found, is a concrete implementation seam to resolve in 40, not permission to simulate deletion in JS or waive AC2.

## Proposed edge-autoscroll oracle to freeze before code

Numbers below are **reversible fixture proposals**, not current product SLA or silently accepted tolerances. Choose/commit them before a candidate run and keep failures visible.

- Fixed viewport1024×768 CSS px, zoom100%, source-bound local font16px/line-height24px, no font network/fallback race, transitions/smooth scrolling/transforms/sticky overlays. Record actual browser/DPR/visualViewport and client boxes; wrong geometry is setup failure. Freeze a separate200% zoom/focus-visible case rather than rescaling a failed baseline.
- One authored 64-row KWDJ surface: each row has a fixed24px block box and text `R00`…`R63`, except R16 is scene_break; R24…R31 are eight paragraph rows inside a quote + bullet-list nesting. Fixture CSS sets paragraph/atom row height and container margins/padding so nesting contributes no uncounted row; actual pre-gesture geometry must match frozen expectations. This is fixture styling, not production semantic layout.
- Down: initial owned anchor Text(R04,1,after), stationary hold beyond bottom edge, exact terminal focus Text(R63,3,after). Up: anchor Text(R59,2,before), hold above top, exact terminal focus Text(R00,0,before). Browser hit coordinates come from bounded fixture-only geometry/literal text probes before input, never production mapping or final observed endpoint. Choose x to hit the independently specified end/start text boundary. Freeze both the semantic table and a separate DOM table (literal text object+offset) before execution.
- Plain geometry: scrollport client box x100/y80/w640/h240, no border. Clipped variant: same scrollport intersected with an authored overflow-clipping ancestor x96/y100/w648/h180. Read **actual** client geometry and verify the fixture. Effective visible rectangle is viewport ∩ scrollport client area ∩ every applicable clipping ancestor; use actual visualViewport bounds if present. A fully offscreen or zero-area intersection is not pass.
- At a checkpoint collapse a fresh native Range at raw focus and require a finite, positive-height caret rect (zero width is valid). All four rect edges must be inside the effective visible rectangle; proposed rounding tolerance≤0.5 CSS px. Partial intersection, selection-union rect, nearest glyph, scrollTop or a screenshot alone cannot satisfy visibility. If the engine supplies no usable focus caret rect, mark instrumentation failure/explicit unresolved gap; do not manufacture one from the expected endpoint.
- Freeze hold target beyond the effective top/bottom edge, observation cadence and finite maximum held duration. Require stationary pointer plus at least two distinct successful scroll advances while held and a path crossing both atom and nesting. Record pointer IDs/buttons, actual heldMs, scroll owners, anchor/focus and rects before/during/after. Anchor identity/offset/affinity must remain unchanged at **every** sample; focus progresses in the intended logical direction. Do not infer a running case from the previous completed one.
- Proposed12-row core matrix =2directions×2geometries×3endings: (a) exact terminal endpoint then release; (b) release while scrolling with additional range remaining; (c) pointercancel while scrolling with range remaining. At a terminal content boundary alone, zero scroll does not prove cancellation. After release/cancel allow at most one explicitly qualified settlement frame, then require five100ms samples with unchanged selection/all scroll owners and no pending RAF/pointer capture/controller continuation. Freeze the exact budget before code; historical20×100ms M0 observation is not an implementation deadline.
- During gestures document bytes/revision/dirty/history/IDs remain unchanged; selection epochs/events reflect actual selection changes only. Lifecycle cancellation (destroy/replace), mode changes, outside pointer ownership and window loss of focus must release the controller safely and never capture unrelated desktop input. Reduced motion must not make the endpoint invisible. Do not assist acceptance with wheel, direct scrollTop, scrollIntoView, injected model endpoint, or reselect-after-gesture.

The oracle records its own actual geometry and gesture; it does not promise identical browser heuristics or scroll speed. M0 Chrome/Safari endpoint gaps motivate 40 and are not production acceptance results.

## Browser/native provenance and bounded ownership

Run the same semantic literals in mounted Chromium/Firefox/WebKit, labeling Playwright keyboard/mouse as automated protocol input. Actual installed desktop **Chrome and Safari EN/RU** additionally require real selection keys and pointer-held gestures with separately retained events/geometry/state/checkpoints; do not call WebKit Safari or automated key APIs physical. Firefox experimental labeling itself grants no permission to weaken configured existing/new assertions or hide mandatory local failures. Determine the applicable engine-specific OSR-40 acceptance status from the fresh contract at Refine. Behavioral GAP/OSR-73 qualification requires sound measurement and explicit contract scope; missing/broken instrumentation is always blocked and cannot be relabelled a behavioral gap.

Native drag harness is **plan only**: dedicated fixture nonce/URL/title/mount identity, bounded coordinate/command allowlist and one pointer owner. Before each actual key or pointer transition require a fresh page acknowledgement plus exact foreground-window ownership guard; capture actual delivery/unknown-completion and cleanup. Use the accepted Safari bootstrap-only Apple Events + same-origin fixture broker architecture; no Apple Events after bootstrap/physical input, and no general desktop-input facility. Unknown completion disables further input; never replay a possibly delivered drag/mutation. Restore only owned input state and close only the uniquely guarded fixture. EN/RU locale changes and restoration failures remain actual receipts, not presumed success. This draft authorizes none of those actions.

One internal scheduler/selection publisher per mount, bounded listeners/RAF/work/retained bookmarks, no full canonical export per selectionchange/pointer tick, no unbounded DOM clone and no browser-native history as a second authority. Cancel every continuation on invalid ownership/generation or destruction; resources and native handles return to their recorded baseline. Composition/provisional regions retain current39 preservation guarantees; full IME exactly-once behavior is OSR-41, not a reason to force a bookmark through pending input.

## Decisions required at fresh Refine, without narrowing the five AC

1. Internal-only versus thin public bookmark access; exact refusal names, bounded retention, and explicit mapped policy for document-only epoch changes versus newer user intent. Existing generated/native shapes stay authoritative.
2. Native command reachability for selected-range cut/delete/format across basic lists/atom: inventory actual positive supported contexts, specify any minimal missing native seam, preserve typed incompatible-profile refusals. Do not count renderer gates as universal AC2 success.
3. Freeze plain-text structural copy projection, geometry/font/clip/hold/tolerance/cancel budgets and independent exact endpoint tables before candidate execution. Choose the supported scroll owner and pointer ownership/cancel policy; no custom bidi or virtualization rewrite.
4. Keep full clipboard47, IME41, toolbar42, DnD44, virtualization46, future domain renderers/AT/Firefox promotion outside implementation scope while retaining the explicit selection/ownership seams they need. No OSR-38 campaign, benchmark or stopped block is reopened by this task.
