# Controlled RU filtering versus installed input

Browser development10 preserved a Firefox protocol failure: keyboard.type of
`/цит` committed the ordinary slash, then reached the existing41
`dom.composition_ambiguous` refusal for Unicode transport. That result remains a
failure of that attempted transport; it is not reclassified as ordinary typing.
Composition41 policy and its original assertions remain unchanged.

The mounted RU heading/filter/pointer scenario now uses a real browser-protocol
slash key, followed by three explicitly controlled cancelable beforeinput events
for ц, и, т. It requires exact native canonical/query/command/caret results and
the actual trust vector true/false/false/false. These events exercise ordinary
owner publication and bounded native witnesses; they do not prove physical RU
typing, a Firefox IME window or installed input. Native Chrome/Safari RU cases
retain the independently frozen existing-source/Carbon translation protocol.
