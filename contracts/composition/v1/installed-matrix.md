## Closed fixture and physical transport

Use a new composition41 fixture/protocol on the actual packaged SDK2/DOM/KWDJ
candidate. Existing40 foreground/AX/physical helper foundations may be reused;
their old fixture cases/guards are not silently reclassified as this matrix.
Closed fixture methods expose finite prepare/guard/observe/finish operations,
not general eval or arbitrary native RPC. Guard exact source/build/fixture,
mount/case/nonce, foreground PID, own tab/title/AX viewport and fresh bounded
physical coordinates before every action. Preserve raw pre/post guard, helper
reply, actual trusted event trace, ownership/correspondence and native outcome.

Physical input requires an acknowledged actual owning browser event. A helper
`sent`, script exit0, correct final text, synthetic KeyboardEvent or RU layout
selection alone is not proof that a physical operation completed. Reuse the
existing one-second action guard bound and failfast on an unknown/timeout or
assertion failure. Unknown input is not retried or silently released/replayed as
a new command. Preserve any emergency key-release record and original failure.

Setup may install the independently authored directed raw DOM selection before
the first physical action and verify the actual owning object/path/offset. It
must synchronize to native and capture the declared post-setup baseline. During
composition no JS text/range setter, host DOM mutation, remount, test repair,
native direct edit or synthetic composition event is allowed. Only bounded
observation and the production adapter's normal operation proceed.

For the actual dead key, record physical Option down, E down/up while Option is
held, Option release, then unmodified E down/up. Both modifier release and text
events are actual readbacks. Record trusted composition/input observations,
isComposing, actual Text contents and object references, event.data (diagnostic
only), settlement reads/times and the original native ticket. Do not assume a
particular event ordering, trust bit on every end event or nonempty end.data.
Before any next ordinary action wait for the current closed fixture's bounded
terminal readback; do not supply a second completion character to rescue a case.

## Checkpoints, identity and cleanup

Capture baseline, provisional interval, end checkpoint, stable settle, original
ticket completion, native state/history/map, presentation, undo/redo, and finish.
Use literal raw DOM child paths from `dom-oracles.json`, not a production mapper
as the expected endpoint source. Pin protected/outside actual objects and attrs
at each applicable checkpoint. Distinguish UA Text replacement from unchanged
Text characterData and from an adapter detach/remount; no universal claim that
MutationObserver identifies a writer. No native begin/end callback may steal
focus from the external control.

Document revision/selection/stored marks/history/dirty/IDs/maps use the independent
native expectations and declared setup baseline. Exactly-once means one actual
isolated InsertText, one document event and one undo unit, not merely final text
equality. Failed/refused/unknown tickets retain their original status. An SDK
queued ticket remains the original ticket and is never retried by the fixture.

Every finish retains raw errors/CSP arrays, exact native/SDK/DOM/selection/
clipboard/composition resource readbacks, pending settle RAF/timer/ticket counts
and host-recovery ownership. After actual terminal completion, all adapter/SDK
resources are zero. A transferred recovery owner is separately acknowledged or
preserved, never silently destroyed to manufacture zero. Restore the pre-run
layout (normally US), close only owned Chrome window/Safari fixture tab, retain
cleanup proof and actual helper byte/hash/modes before/after. Do not claim Safari
application shutdown or zero AppleEvents: System Events physical keys may use
AppleEvents; post-bootstrap Safari app scripting/JS/navigation is separately
qualified by the transport.

## Lane boundaries and honest failures

Chromium/Firefox/WebKit controlled measurements use all frozen assertions. A
sound observed Firefox behavior limitation may be GAP with its actual measurement
and preserved recovery, while setup failure, stale overwrite, missing input,
wrong offsets/data or broken assertions remain FAIL. No skip/filter weakens a
mandatory controlled or installed positive. WebKit is not installed Safari;
synthetic pointer/composition/cancel is not physical input; CJK/mobile/real AT and
Firefox promotion73 are outside this matrix.

The historical Safari early-space observation (actual U+0020 event data, U+00A0
DOM change before later Space keydown) remains **AMBIGUOUS negative/recovery**.
It is not a required positive or proof of a separately owned ordinary input.
No data/inputType/trust/time heuristic, late keydown, retrospective permit or
unexplained changed tombstone tail may turn it into a second composition commit.
