# SDK ABI1 literals

`vectors.json` contains independently authored KWDJ v1 documents and expected SDK outcomes. The sixteen command cases cover the frozen compiled KWDJ command catalog. Expected canonical document bytes are plain deterministic JSON serialization of those literals, never generated by KWDJ admission, normalization, command execution or snapshot export.

The same `sdk_observer.rs` invokes the real public Rust `BridgeSession` through JSON DTO encoding/decoding in native and compiled WASM lanes. It checks opening negotiation before document decode, strict/import distinction, all command query/execution pairs, independent before/after canonical documents, exact historical identity revival, captured context refusals, revisioned node reads, reverse Text/Child/Edge positions, null versus explicit empty marks, event peek/ack, mapping, remount, mutable reference facts, snapshot receipts/save baselines and native resource bounds. Dynamic opaque identities and target-dependent ownership byte estimates are compared within each target and omitted from portable reports.

Snapshots are explicit test checkpoints. These tests do not instrument ordinary profile codec calls and make no new claim about zero ordinary codec hooks; that invariant remains covered by the existing command/history/delta witnesses. Native bridge resource checks do not claim JS loader/scheduler/listener behavior, packaged installation or browser CSP coverage; those have separate OSR-63 gates.

Literal caret expectations are included where specified in each command vector. Other command cases verify independent document behavior and native selection validity without inventing a new caret policy. These cases supplement the existing command/history goldens and are not general fuzz/performance acceptance.

During initial observer authoring, two caret/insertion assumptions were corrected against the existing OSR-35 contract: text-caret block insertion splits around both headers, and structural remove chooses its parent gap. The root-gap insertion/removal cases now state those positions explicitly; the text-caret code-block case reuses the frozen OSR-35 structural literal, and slash insertion reuses KW35-020. Initial failed raw logs are retained separately and are not product regressions.

The Null attribute negative case expects the frozen borrowed command-mark shape diagnostic `kwdj.invalid_structure`, qualified by its `/stored_marks` path. This follows baseline `62a52bb` `validate::canonical_command_marks` / closed shape guards, which already predate this SDK. It does not equate that borrowed generic-shape diagnostic with the separate owned-wire `kwdj.unknown_attribute` category, and changes no production error code. The observer preserves the direct Null DTO roundtrip before that profile rejection.

Limit DTO field `text_leaf_bytes` retains the existing KWDJ diagnostic limit name `text_length`; the ceiling probe pins that baseline validator name and its exact maximum/observed decimal strings.

The closed-unit request negatives also exposed a real SDK DTO issue: serde had accepted unknown fields on internally tagged unit variants. Those negatives stayed failing until the DTO variants were repaired to closed empty structs. The actual defect red log is retained separately from the authoring-assumption corrections above.
