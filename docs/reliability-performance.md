# Production reliability measurements

OSR-38 uses `editor-reliability-performance/1`. The protocol and independent synthetic distributions in `perf-protocol.mjs` were authored before runtime capture. Synthetic tests establish comparator arithmetic and refusal rules; they are not production measurements.

Each case has at least five distinct process launches per side and 200 samples per launch. Baseline/candidate launches interleave. Nearest-rank p50/p95/p99 are computed per run; the comparison uses the median run-p95, reports its range and sample CV, and keeps every original sample. CV above 10%, incomplete samples, source/environment/harness mismatch, corrupt hashes, censored samples or insufficient timer resolution yield `INCONCLUSIVE`. A timer p95 must contain at least 100 observed timer increments and at most 1% zero samples. Neither batching nor quantile subtraction silently manufactures a core latency.

The 200-sample definition covers per-operation latency, actual allocation deltas and live checkpoints. Whole-process allocator peak and sampled process RSS each contribute one genuine scalar per independent launch, at least five launches per side. They use median/range/sample CV and the same adopted-floor/relative/independent-confirmation policy; they do not claim 200 samples or per-process p99. This dimension-specific policy was accepted before capture in `evidence/osr-38/memory-sampling-decision.md`.

A regression exceeds both the adopted absolute floor and `max(20%, 3 × baseline CV)`. The first batch yields `NEEDS_CONFIRMATION`; a second independent batch with the same frozen inputs must reproduce the regression to yield `FAIL`. A non-reproduced first regression stays inconclusive. Shared CI noise cannot close reference acceptance.

Accepted OSR-64 is the baseline; OSR-38 is the candidate. Source/artifact identities, release flags, hardware, OS, toolchains, corpus, seed, harness and power/load observations accompany raw captures. Command and allocator absolute floors remain **unadopted until actual stable accepted64 calibration**. Existing export 0.2 ms, startup 5 ms and RSS 32 MiB floors retain their earlier scope. No product SLA is introduced. Identical production paths establish a protocol baseline rather than a speedup.

Required attribution separates public native core operations, native/actual-WASM bridge calls, packaged SDK runtime delivery, exact WASM memory capacity, native allocator whole-process live/peak, logical retained resources, JS resources, sampled RSS and bundle bytes. A fresh allocator process owns each profile/workload; all-time peaks are never subtracted to claim a window peak. DHAT includes declared harness allocations and instrumentation overhead and is not compared with uninstrumented latency. Actual WASM Memory must come from the same initialized instance used by the SDK; no public memory setter is added.

The DHAT 0.3.3 backend explicitly uses its supported minimum `trim_backtraces(Some(4))`, replacing its default `Some(10)`. This limits captured backtraces and can merge allocation-site attribution; it does not turn off instrumentation or change its global allocation/live/coherent-peak definitions. DHAT still captures unlimited initialization traces at profiler startup and the first profiled allocation. The earlier default-10-frame partial reference capture is incomplete calibration evidence, preserved without promotion. A source-bound small-control comparison checks exact global counters against the retained default-10-frame release binary before rebuilding both matched producers and authorizing a fresh full capture; no allocator timing speedup is inferred from that control. See `evidence/osr-38/dhat-instrumentation-decision.md`.

The corrected capture schedule completes all five timing rounds before the five allocator rounds. Baseline/candidate AB/BA order remains within each round; all required cases and samples remain present. The sealed schedule binds each launch to its phase and position. This ordering excludes profiler launches between timing rounds within the capture and makes no claim about external host conditions.

The completed corrected reference collected all 410 launches / 1040 metric runs, but all 104 time cases failed the unchanged 10% CV guard; 104 resource cases were stable. No floors or policy were adopted and no candidate comparison ran. Current raw validation passed separately from an incomplete historical capacity executable witness. See [the recorded outcome](../evidence/osr-38/phased-calibration-quality-checkpoint.json); OSR-38 acceptance remains incomplete.

Seven profile-valid shapes cover long leaves, many blocks, deep ancestors, lists, tables, near-node and near-canonical-byte ceilings. Unsupported Notes list/table capabilities are explicit. Default-limit 4096-command sessions drain real delivery events without changing limits; capped recurrence and isolated admit/destroy are separate workloads. Renderer measurements begin in OSR-39; installed-browser release acceptance remains OSR-71 and bundle cap adoption remains OSR-80.

The comparator also checks every run's unit, exact paired consecutive rounds, raw sample bytes/hash/pointer, unique sealed launch provenance and nonoverlapping AB/BA order. Calibration supplies its complete sealed accepted-source raw capture, matching source/harness/environment, adequate stable samples, and a real adoption timestamp after calibration completion and before candidate launch. Confirmation needs disjoint launch IDs and a later nonoverlapping capture interval. A relabelled copy cannot confirm a regression. `integrity: invalid` is distinct from honest measurement noise; the analyzer exits nonzero for invalid evidence. With `requireConclusive:true`, anything short of full-plan `PASS` fails reference acceptance.

Observed timer increment is checked against the bound raw output. Logical requests retain their exact document/registry strings, options, sample/warmup/step counts and layer; only distribution deployment root is excluded from the cross-side workload hash. Retained request bytes, reconstructed complete stdin, per-case calibration/round pairs and confirmation must agree. Requests are stored once per workload as deterministic gzip; raw launch/stdout/stderr and compressed/uncompressed hashes are rechecked before analysis.

Preparation and execution use explicit JSON configs, never hidden benchmark work during imports or `npm check`:

1. `node scripts/reliability/perf-build.mjs build-config.json` builds each side from an actual `sourceRoot`/`sourceCommit` with the same `harnessRoot`, fresh `outputRoot` and optional `gitRepository` for an exported source tree. Every runtime blob matches that commit. It preserves locked fetch/build logs and exact native artifact hashes. The benchmark binary has no allocator wrapper; the separate allocator binary enables `allocator-profile`.
2. Run the source-bound fixed Notes capacity ladder first with `perf-capacity.mjs`, as frozen in `evidence/osr-38/notes-capacity-decision.md`. It preserves maximal typed controls and separately freezes jointly feasible command/export rungs. `perf-capture.mjs` takes the immutable `notesCapacity` receipt. A candidate capacity verification supplies `reference` and actual `sourceCommit` and compares every rung's admission/command/export outcome without reselection. Then `node scripts/reliability/perf-capture.mjs calibration-config.json` requires `authorizedQuietCapture:true`, `mode:"calibration"`, a new output/batch, `rounds:5`, `samples:200`, `warmup:64`, and a baseline `{sourceCommit,nativeBuild,distributionRoot}`. Native build receipts and actual packaged SDK seal/build/runtime sources are checked before capture. Default plan includes all supported shapes/layers, small explicit exports/lifecycle, default4096 sessions, capped recurrence and fresh-process DHAT. A reduced plan must declare `diagnosticSubset:true` and cannot close reference acceptance.
3. `node scripts/reliability/perf-capture.mjs calibration-proposal baseline.json` reports actual quantiles/CV and leaves new floors null. After a stable calibration, an explicit config for `perf-policy.mjs` supplies `calibration`, actual `candidateSource`, `floors` with every case's `absoluteFloor`/`rationale`, overall `rationale` and a new `output`. Existing protocol floors cannot be changed. This writes an adoption before candidate launch; no candidate result chooses a floor.
4. Comparison capture adds `mode:"comparison"`, both sides, the immutable `policy` and `calibration` paths, a fresh batch/output, and identical other inputs. Launches alternate AB/BA by round. Quiet mode is a primary-agent coordination gate; the runner records actual power/load observations and never claims thermal controls it did not measure.
5. `node scripts/reliability/perf-analyze.mjs analysis-config.json` reads `baseline`, `candidate`, `calibration`, `policy`, optional independent `confirmation:{baseline,candidate}`, optional `output`, and `requireConclusive`. It rehashes every raw file and validates the full default plan. Exit1 means invalid evidence;2 means confirmed regression;3 means required reference evidence remains inconclusive/unconfirmed. Without `requireConclusive`, honest shared-CI noise is retained successfully while its status remains inconclusive.

Native requests resolve the current authored path outside timed work because replacing a whole leaf legitimately retires its old identity. Command timings include actual command preparation/publication; bridge timings include its JSON boundary; SDK timings include awaited runtime delivery. Initial/final canonical checkpoints, selection setup, path reads and explicit event acknowledgement stay outside command timing. Export timing includes the public snapshot boundary and its returned bytes; release is outside. Lifecycle timing includes actual admit/close/drop through its declared layer; the packaged module is initialized once outside repeated lifecycle samples. DHAT includes request decoding, corpus ownership, harness bookkeeping and result construction; per-operation allocation deltas are taken immediately around the declared operation, live values are true checkpoints, and final process peak is the sum of DHAT allocation-site `gb` values at the same global maximum, never the sum of unrelated site peaks.

Cold packaged startup is a separate genuine process scalar around production SDK import, seal verification, compilation and instantiation of that single actual module; it retains the existing5ms startup floor. Warm lifecycle/admit-destroy does not borrow that cold-startup floor and requires its own stable calibration/adoption. Native constructor/admission observations remain explicitly scoped and are not reported as WASM startup.

`perf-bundle.mjs` records actual delivered JS/WASM raw and deterministic per-file gzip hashes/bytes. Its summed per-file gzip sizes are labelled as such, without claiming a deduplicated bundler result or adopting OSR-80 ceilings. All script imports are inert. Original failed harness assumptions and correctness smoke runs remain development evidence and are never promoted into release measurements.
