# Бюджеты текстовых проекций KWDJ

OSR-74. Валидность хранения и возможность построить проекцию — разные проверки.
Семь нормативных максимумов v1, schema_version, нормализация и canonical JSON
не изменены. Большое `stanza_break.blank_lines` может оставаться валидным
авторским значением, при этом вычисление проекций возвращает отказ. Текст не
обрезается, число пустых строк не уменьшается, документ не переписывается.

`ValidatedDocument::project_text()` и `NormalizedDocument::project_text()` теперь
возвращают `Result<ProjectionResult, ProjectionError>`. Метод
`project_text_with_budget(ProjectionBudget)` позволяет хосту уменьшить лимиты.
Каждое поле ограничено соответствующим библиотечным потолком, даже если хост
передаст `u64::MAX`:

| Поле | Потолок на один вызов | Что считается |
| --- | --- | --- |
| output_bytes | 4 MiB | UTF-8 байты каждой промежуточной/итоговой строки |
| work_bytes | 128 MiB | Сумма всех добавленных/скопированных байтов, включая вложенные joins и отдельную search-копию |
| node_visits | 200 000 | Посещения при обходах full/snippet, включая пустые узлы |

Это консервативные эксплуатационные потолки, а не измеренный production SLA.
4 MiB дают запас над 2 MiB canonical payload для серверных меток/разделителей;
128 MiB ограничивают повторные копирования во вложенных контейнерах; node budget
останавливает работу даже без выходных байтов. Документ, исчерпавший любой из
потолков, сохраняет валидность хранения. При необходимости host может выбрать
более строгие значения; повысить эти потолки без пересмотра реализации нельзя.
Полный результат содержит три строки; одинаковые full/search имеют отдельное
владение, и обе копии учитываются. `String::try_reserve` использует амортизированную
ёмкость аллокатора: лимит относится к длине, а не точному размеру heap allocation.

Все сложения длины выполняются checked. `1 + blank_lines` и прибавление к уже
имеющейся строке могут вернуть ArithmeticOverflow. Объём проверяется **до**
reserve, преобразования в usize и цикла разворачивания. Ошибка выделения памяти
также типизирована. Refusal возвращает только тип/код и числовой лимит; авторское
содержимое и частичные проекции в ней отсутствуют. Ошибка на поздней стадии,
включая создание search-копии, не выдаёт ранее вычисленные строки потребителю.

Ошибки: `kwdj.projection_output_budget_exceeded`,
`kwdj.projection_work_budget_exceeded`, `kwdj.projection_node_budget_exceeded`,
`kwdj.projection_arithmetic_overflow`, `kwdj.projection_allocation_unavailable`.
Потребитель обязан обработать отказ до writer/publication side effects; нельзя
подставлять пустую/частичную проекцию или паниковать через unwrap в runtime.
CMS интегрирует этот Result и обновляет immutable source pin в той же OSR-74.

Native tests и test-only compiled WASM example выполняют одинаковые синтетические
сценарии: u64 overflow/huge expansion, точные/нулевые/исчерпанные лимиты, попытку
поднять потолки, неизменность canonical JSON, обычные пустые строки, UTF-8,
spoiler/caption/table bytes. WASM example строится в `artifacts/projection-budget`,
проверяется в Chromium/Firefox/WebKit под прежним CSP и не входит в package dist.
Это тест семантики профиля, а не публичный session/codec API из OSR-33/63.
